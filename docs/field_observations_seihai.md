# 実地観測ログ — seihai ループからの by* 失敗記録

**この文書の位置づけ。** seihai（FX 自動改善ループ）は contra の by\* ツールを**毎日・実運用のテーマで**呼んでいる唯一の常設利用者である。そこで出る失敗は、開発中のテスト実行では再現しにくい**同一テーマ族での長期反復**という条件下の観測であり、**改善のための一次データ**として扱う。

**分担**:

- **seihai = 観測者**。by\* が (i) 収穫ゼロ、(ii) スコア 0.0 の定型文、(iii) 明らかに無関係な上位結果、のいずれかを返したら、その日の insights に書くだけでなく**ここに1行追記する**。seihai 側では contra のコードを直さない。
- **contra = 被験体**。対処はスケジュールタスク **`contra-failure-remediation`（火・金 21:00）** が担う。ここを読み、失敗様式を1つ選んで直し、`Changelog.md` / `DECISION_LOG.md` に結果を書き、この文書の該当行に対処状況を付ける。

**書式**（1行1観測。数値は可能な限り実測値で）:

```
| 日付 | ツール | テーマ | 失敗様式 | 実測値 | 対処状況 |
```

## 未対処の失敗様式

### F-01. bybridge — 巨大ハブ吸着（7週連続・**seihai 側で 2026-08-16 に呼び出し停止**）

**症状**: 交差候補の上位が毎回「共有 bridge 1本」で、内容は分野を問わず**汎用の超高被引用ハブ**に潰れる。過程（シード30／bridge プール50／交差候補60）は正常完走するので**故障ではない**。

| 日付 | テーマ族 | 上位に出たハブ（被引用数） |
|---|---|---|
| 〜2026-08-01（5週分） | アルゴリズム取引・戦略生成 | TAM(43,317) / Felsenstein ブートストラップ(41,579) / SEM 二段階法(40,027) / PLS 回帰(9,798) / Efron ブートストラップ(6,162)。**AT&T Labs という書誌データの欠損レコードまで混入** |
| 2026-08-08 | 同上 | 上位10件すべて共有 bridge 1本 |
| 2026-08-11 | 同上（シード配置を変更） | 上位10件すべて共有 bridge 1本（量子化学 DFT）。**シードを変えても同じ** |
| 2026-08-15 | 同上 | 上位3件すべて共有 bridge 1本（集団遺伝学＝中立性検定 7,260／中立群集理論 5,710／ボトルネック検出 4,377）。**セレンディピティ・スコアは3件とも 0.0（構造スコア 0.0）**、生成散文は「転用できるか要検討」の定型文のみ |

**診断（seihai 側 S-38）**: 失敗様式は「ホームドメインへの回帰」ではなく **巨大ハブ吸着**。したがって処方は**ドメイン除外ではなく中心性ペナルティ**——bridge プール構築時に被引用数・次数で正規化する、または degree 上限を設ける。実装先は `src/pipeline/bridges.py`。

**却下済みの対処**: 「共有 bridge が1本だけの交差候補を捨てる（最低2本要求）」は seihai 側 M-16 として起票されたが 2026-08-02 にユーザー裁定で DROPPED（「シードを調整すれば解決する」）。**その後シード配置を変えても再現した（8/11）ので、この前提は実測で否定されている。**

**正直に記録すべき1点（2026-08-15）**: 3件目「対立遺伝子頻度からの最近のボトルネック検出」は**構造的にはその週の問いそのもの**だった（残っているものの組成から、母集団が最近枯渇したことを検出する）。**しかしこの転用はツールが与えたのではなく、読み手がタイトルから作ったものである。** ツールは 0.0 を付けて定型文を返していた。⇒ **「たまたま隣に落ちていた」を「効いた」と数えない。**

**再開条件**: 中心性ペナルティ実装後に seihai 側で再開し、**最初の3回で失敗様式が変わるかを測る**。変わらなければ本テーマ族への恒久的な不適合として除外する。

### F-02. bybridge — 使ったシードが出力に含まれない（S-11）

**症状**: 出力は「シード 30 件」と**件数しか返さない**。シードが見えない限り、呼び手は失敗が「シード検索の失敗」なのか「橋が汎用ハブに吸われた」なのかを**原理的に区別できない**。

**実害**: M-16 の裁定根拠が「シードを調整すれば解決する」だったのに、**調整の効果を測る手段が無いまま5週が経過した**（裁定の前提が検証不能）。

**対処案**: `bybridge_collect` の戻り値に使用シード（タイトル・DOI・被引用数）を含める。F-01 の中心性ペナルティより**先に入れるべき**——効果測定の計器がないまま処方を入れると、次も「効いたかどうか分からない」で終わる。

### F-03. byrepo — 関連度がランキングに効かない（S-39）

**症状**: `Reliability Score` はリポジトリ品質（Impl/Doc・LMA・Community・Security）のみを測り、**テーマ関連度をスコアに含めない**。「関係度: 中」はラベルとしては出るがランキングには効かないため、**無関係だが良く整備されたリポジトリが上位を占める**。

**実測**: 2026-08-15 時点で**5週連続の収穫ゼロ**（8/15 は「見つかりませんでした」）。2026-08-07 に語彙を MLOps 系へ切り替える改善仮説を試したが**外れた**。

| 日付 | テーマ | 上位3件 | 実測 |
|---|---|---|---|
| 2026-08-10 | 配備アーティファクトと稼働インスタンスのバージョン乖離検証 | `garrytan/gstack`(127k★) / `Mininglamp-AI/Mano-P` / `VoltAgent/awesome-agent-skills` | 3/3 無関係。関連性の散文はテーマ側の語をリポジトリに貼っただけ |
| 2026-08-17 | 逐次実験の多軸停止規則・futility boundary・arm dropping の実装 | `brownjuly2003-code/ab-test-research-designer`(★1・**Reliability 79**) / `aladinor/rustytree`(★8・**75**) / `Lexsi-Labs/aligntune`(★38・**84**) | **1/3 のみ主題に接する。しかも最上位スコアは無関係な `aligntune`(84) で、唯一関連する候補が 79 と下**＝F-03 の症状（関連度が順位に効かない）が**同一出力内で直接観測できた形**。`rustytree` は Zarr/xarray の Rust バックエンドで、生成散文は「非同期処理能力を活用し停止規則を同時評価できるかもしれない」という**リポジトリの実体に対応しない転用**を書いている |

| 2026-08-18 | GP 生成器の候補相関と集合レベル PBO 大域veto の分離／生成段での behavioural diversity 強制 | `impratiksingh/unsupervised-learning`(Kaggle・★1605・**Reliability 28**) / `azxc9595/visual-graphs-of-philosophy`(Kaggle・★696・**28**) / `arunkumarramanan/awesome-ml-frameworks-and-mnist-classification`(Kaggle・★329・**24**) | **3/3 無関係、かつ 3/3 が Kaggle ノートブック**（`sources` 既定に github を含めて呼んだが、上位はすべて Kaggle）。Impl/Doc・LMA・Comm・Sec が**全件 0/0/0/0** で、スコアは実質★数の単調変換になっている＝**品質軸すら測れていない**。`keywords_include` に `quality diversity` / `novelty search` / `backtest overfitting` を明示したのに、QD/GP 系のリポジトリ（`pyribs`・`qdpy`・`gplearn` 等の明白な候補）が1件も上位に来ない |

★**2026-08-17 の観測が F-03 の診断を強める**: 従来は「無関係が上位を占める」という結果からの推定だったが、今回は**関連する候補が実際に返っており、それがスコアで無関係な2件に負けている**。⇒ 対処は検索語彙の調整ではなく、**関連度をスコアに乗算項として入れる**（下記対処案）で確定してよい。

★**2026-08-18 の観測が加える別軸**: この日は**全件 Impl/Doc=LMA=Comm=Sec=0** で、順位が★数だけで決まった。F-03 の対処（関連度を乗算項に）を入れても、**品質軸が全ゼロに潰れる経路が残っていれば順位は人気度のままになる**。⇒ 対処案に「**品質サブスコアが全件ゼロで返る条件を先に特定する**」を追加する（Kaggle 由来のアンカーで各サブスコアが埋まらない疑い）。

**対処案**: (1) 関連度をスコアに乗算項として入れる。(2) 品質サブスコアが全件 0 になる経路（少なくとも Kaggle 由来）を特定して埋めるか、埋まらない source を順位付けから外す。

### F-05. byrepo — 「概要」が**ソースでなく呼び手のテーマ**を要約して返る（2026-08-18 初観測・F-04 と同一機序）

**症状**: 返却された各アンカーの「1) 概要」が、**そのリポジトリ／ノートブックの内容ではなく、呼び手が送ったテーマ文の言い換え**になっている。呼び手はソースを開かない限り、これを「関連する資料が見つかった」と読む。

**実測（2026-08-18）**: `azxc9595/visual-graphs-of-philosophy`（哲学の可視化グラフ）の「1) 概要」が —— 「本研究は、**遺伝的プログラミングによる売買ルールの自動生成における候補集合の相関問題**を探求し、過剰適合指標が閾値を超える原因を分析する。特に、生成段での多様性を強制する手法が効果的であることを示唆している」。**これは送信したテーマ文そのもの**であり、当該ノートブックはこの主題を扱っていない。`impratiksingh/unsupervised-learning`（MNIST 系の教師なし学習ノート）の概要も同様に「データの多様性を保ちながら効果的な特徴を学習する手法に焦点」と、テーマ側の語（多様性）を主題として貼り直している。

**F-04 との関係**: F-04（byserendipity が「2) 関連性」の**テーマ側**命題を捏造する）と**機序が同じで向きが逆**。F-04 はテーマ側の命題を作り、F-05 は**ソース側の内容**を作る。どちらも「出力の散文が、入力テーマを条件にした生成であって、ソース本文に接地していない」ことの現れ。⇒ **F-04 の対処案（テーマ側命題を提出テキストからの抜粋に限定する）と対になる規約が要る＝ソース側の記述も README/abstract からの抜粋に限定し、抜粋できないなら概要を出さない。**

**なぜ危険か**: F-01（bybridge）は構造スコア 0.0 で**失敗を自己申告**していた。F-04/F-05 は**成功の形で失敗する**。しかも F-05 は概要・関連性・仮説の3節すべてが整合した散文になるため、**ソースを開かない読者には検証の取っ掛かりが無い**。

### F-06. bynote — 「他ドメインの類推」が全件ホームドメイン内（2026-08-18 初観測）

**症状**: `bynote_link_concepts` の「2. 類推可能な**他の**抽象的ドメインの例」が、テーマのホームドメイン（進化計算・機械学習）そのものから3件返る。

**実測（2026-08-18）**: テーマ＝GP 生成器の候補相関と集合レベル PBO veto。返却された3ドメイン＝**(1) 機械学習モデルのハイパーパラメータ最適化 / (2) 進化的アルゴリズムにおける個体選択 / (3) ネットワークトポロジーの最適化**。(2) は**テーマそのもの**（GP＝進化的アルゴリズムの個体選択）で、距離ゼロ。(1) も同じ「探索と過剰適合」の圏内。Serendipity Bridge の問い（「どのような外部要因を導入すれば生成器の出力を変えられるか」）も、テーマ文が既に問うている内容の再掲。

**bybridge/byserendipity の失敗様式との違い**: あちらは**遠くに行って構造を捏造する**。bynote は**遠くに行かない**。同じ「距離×構造の乗算選別」の両端で別々に壊れている＝**距離項と構造項が独立に故障しうる**ことの実地例。

**対処案**: 出力ドメインに対して、テーマの `scope_field` との**分野距離の下限**を課す（同分野のラベル違いを弾く）。少なくとも「テーマ文に既出の語で記述できるドメイン」は候補から外す。

### F-04. byserendipity — 「関連性」がテーマに存在しない命題を相手に立てられる（2026-08-17 初観測）

**症状**: 返却された論文の「2) 関連性」欄が、**テーマ側の命題として提出していない文**を引いて対応づけを主張する。スコアは 0.0 ではなく中位（0.56）で、接続点ラベルには自ら「**構造対応ゆるめ・思考のタネ**」と書かれる。

**実測（2026-08-17・テーマ＝「単一軸の事前登録停止規則が、規則の見ていない軸での劣化に対して恒久的に沈黙する」）**:

| # | 返却論文 | スコア | 主張された対応 | 実測 |
|---|---|---|---|---|
| 1 | The precision–fragility paradox: 生成AIが顧客生涯価値を上げつつ在庫切れを増やす（2025・被引用 **0**・venue "Frontiers in Research"） | 0.56（距離 0.80 / 構造 0.70） | 論文側〈顧客セグメンテーションが供給チェーンの機敏性を制約する〉↔ テーマ側〈**需要の変動が在庫管理の難易度を高める**〉 | **テーマ側の命題が捏造**。提出したテーマに「需要」「在庫」は一語も無い。実際に対応させるべきテーマ側の命題（停止規則の盲点）とは無関係 |
| 2 | Agile Decision-Making in Unstable Markets: A Soft Set Paradigm（2026・被引用 **0**） | 0.56（距離 0.80 / 構造 0.70） | 論文側〈パラメータの変化が意思決定を駆動する〉↔ テーマ側〈市場の変動が意思決定の基準を決定する要因〉 | 対応は成立するが**両側とも汎用命題**で、どんなテーマにも当たる。ただし「4) 注意点」だけは的を射ている（「動的重み付けは変化がリアルタイム観測可能であることが前提」＝こちらは観測されない次元が問題） |

**F-01（bybridge の巨大ハブ吸着）との違い**: bybridge は**構造スコア 0.0 で定型文**を返す＝**失敗を自己申告していた**。byserendipity は**構造スコア 0.70 を付けて、テーマ側に存在しない命題との対応を主張する**＝**失敗が成功の形で返る**。呼び手にとってはこちらの方が危険で、読まずに採用すると架空の類推が insights に入る。

**診断（仮説）**: 距離 0.80 が先に立ち（＝ホームドメインから遠い＝小売/意思決定論）、構造スコアはテーマ全文でなく**要約された断片**に対して付けられている疑い。だから「需要の変動」のような、テーマに無いが**テーマの近傍で自然に生成できる**命題が対応の片側に置かれる。

**対処案**: 「2) 関連性」のテーマ側命題を**提出テキストからの抜粋に限定する**（生成させない）。抜粋できない場合は対応を主張させず、構造スコアを付けない。**被引用 0・新設 venue の2件が同スコアで並んだ**点も併せて、距離項に被引用/venue の下限を効かせるか要検討。
