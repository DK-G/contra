# 実地観測ログ — seihai ループからの by* 失敗記録

**この文書の位置づけ。** seihai（FX 自動改善ループ）は contra の by\* ツールを**毎日・実運用のテーマで**呼んでいる唯一の常設利用者である。そこで出る失敗は、開発中のテスト実行では再現しにくい**同一テーマ族での長期反復**という条件下の観測であり、**改善のための一次データ**として扱う。

**分担**:

- **seihai = 観測者**。by\* が (i) 収穫ゼロ、(ii) スコア 0.0 の定型文、(iii) 明らかに無関係な上位結果、のいずれかを返したら、その日の insights に書くだけでなく**ここに1行追記する**。seihai 側では contra のコードを直さない。
- **contra = 被験体**。対処はスケジュールタスク **`contra-failure-remediation`（火・金 21:00）** が担う。ここを読み、失敗様式を1つ選んで直し、`Changelog.md` / `DECISION_LOG.md` に結果を書き、この文書の該当行に対処状況を付ける。

**書式**（1行1観測。数値は可能な限り実測値で）:

```
| 日付 | ツール | テーマ | 失敗様式 | 実測値 | 対処状況 |
```

### F-08. bynote — 類推は遠いが**構造が空**（2026-08-19 初観測・F-06 の裏面）

**症状**: 「2. 類推可能な他の抽象的ドメインの例」が**ホームドメイン外**（医療試験・製品テスト・教育方法）から返るのに、対応づけが**話題レベル**にとどまり、機序を1つも運んでこない。

★**同日の対照が決定的**: 同じ問いを byserendipity（raw_only・自作 facet 3枚）に投げたところ、facet (i) 医療試験から **[Trials to assess equivalence](https://doi.org/10.1136/bmj.313.7048.36)**（BMJ 1996・被引用 1,032）が返り、これは **「優越性デザインでは同等性を結論できないので、非分離を止めるには専用の事前規則が要る」** という**運べる機序**を持っていた。⇒ **bynote が挙げた「医療試験」というドメインは正しかった。欠けていたのはドメイン選択ではなく、そのドメインの中の実際の文献に降りる段**。

**F-06 との関係**: F-06 は**遠くに行かない**（類推が全件ホームドメイン内）。F-08 は**遠くに行くが何も持ち帰らない**。⇒ 「距離項と構造項が独立に故障しうる」（F-06 の記述）の**構造項側の単独故障**が、これで実地観測された。両方揃って初めて乗算選別の意味が出る。

**対処案**: bynote の類推に**最低1件の実文献接地を要求する**（ドメイン名だけでなく、そのドメインで当該構造を扱った文献を1本挙げさせる／挙げられなければその類推を出さない）。実装としては bynote の類推段から byserendipity の retrieval を1回呼ぶのが最短。

### F-11. 全 by\* 共通 — OpenAlex を**匿名プール・リトライ無し**で叩いている（2026-08-21 起票／**(1)(3) 同日対処済み・(2) polite pool のみ据え置き**）

**症状（潜在）**: `OpenAlexClient.get`（`src/openalex/client.py:42`）は **HTTP エラーを一切リトライしない**——`urllib` の例外をそのまま `OpenAlexError` に包んで送出する。加えて `mailto` は **CLI の `--mailto` でしか渡らず、MCP 経路（`src/mcp_server.py` の `CollectConfig()` 既定）では常に `None`**＝OpenAlex の**匿名プール**を使っている。匿名プールは polite pool（mailto 付き）より共有レートが厳しい。
