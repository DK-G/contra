論文ブレインストーミング支援Webサービス

plan.md（マスター仕様書）

1. 目的とスコープ
1.1 目的

本プロジェクトは、研究・企画・プロダクト設計における
**「テーマ設定前後のブレインストーミング工程」**を支援することを目的とする。

特に以下の課題を解決対象とする：

文献レビューが「正しさ」重視に偏り、疑問形成が後回しになる

初期仮説の前提・弱点が暗黙のまま進行しやすい

量と質のトレードオフにより、思考素材が不足する

問題発覚が後工程にズレ込み、修正コストが跳ね上がる

本サービスは、
「論文を読む前に、疑う・比べる・眺めるための思考素材を大量に提示する」
ことにより、初期段階で問題が発覚しやすい構造を提供する。

1.2 想定ユーザー

大学院生・若手研究者（テーマ探索・レビュー前段階）

研究志向の個人開発者・企画職

新規分野に入る社会人研究者

※ 学部初期層は主要対象外（無料サンプル等で対応）

1.3 MVP（最小実用製品）のスコープ

単一テーマ入力に対する論文自動収集・分類

各論文について、定義された3行構成のMarkdown出力

1テーマ＝1Markdownファイルの生成

履歴保存なし・再生成不可でも成立する設計

1.4 スコープ外（MVPでは扱わない）

論文の精読支援・全文解析

引用関係グラフの可視化

学部生向け教材用途

研究の正解・結論の提示

自動レビュー・査読代替

2. 設計原則・基本方針

要約ではなく「関係性の再構成」を行う

関連論文だけを集めない

強引でも切り口を明示する

解釈はユーザーに委ね、材料だけを過剰に出す

質を最初に最大化し、量は後から拡張可能にする

Markdownを最終成果物とし、外部ツール連携を前提とする

3. サービス概要
3.1 コンセプト

論文を「読む」前に、「疑う・比べる・眺める」ためのツール

ユーザーが入力したテーマに対し、
論文を自動収集・分類し、各論文について AI が
「テーマとの関係性」を3行構成で記述する。

3.2 特徴

関連度の高い論文だけでなく
反証・評価の地雷・制約条件が異なる論文を意図的に混在

Abstract要約ではなく
テーマとの関係性を起点に再構成

精読前に
論点・弱点・ズレを可視化

6. 無関係論文セクション設計
6.1 目的

ユーザーのテーマが持つ
前提・弱点・限界を強制的に露出させること

6.2 章構成（200本）
第1章：反証・対立仮説（50）

仮説や前提を否定・相対化する研究

第2章：測定・評価の地雷（50）

指標・実験設計・因果推論・バイアスの問題

第3章：手法転用（50）

対象は異なるが、解析手法・モデルが近い研究

第4章：制約条件が真逆（50）

スケール・コスト・リアルタイム性などが異なる研究

→ 「このテーマ、どこが危ないか」が一目で分かる構造

4.x 将来的な収集ソース拡張（発展形構想）
4.x.1 位置づけ

本サービスの本質は
「テーマに対して、異なる前提・文脈・評価軸の思考素材を強制的に並べること」
であり、論文データベースに限定されるものではない。

将来的には、
研究成果・実装・議論が蓄積されている他の公開知識基盤も
同一のブレインストーミング構造に統合することを想定する。

4.x.2 拡張対象候補（例）
A. Git リポジトリ（研究実装・実験コード）

対象例：

GitHub / GitLab 上の公開リポジトリ

想定される価値：

論文では語られない「実装上の制約」「再現性の壁」

実験がどこで破綻しやすいか

手法が実際に使われている文脈の把握

論文との差分：

理論よりも 現実的制約・失敗パターンが露出しやすい

B. 技術メモ・設計記録系（将来候補）

例：

技術ブログ

公開研究ノート

設計ドキュメント

想定価値：

仮説形成前後の思考の揺れ

採用されなかった設計・却下理由

※ これらは 信頼性評価・ノイズ対策が必要なため、初期MVPでは扱わない

4.x.3 論文との統合方針

拡張ソースは、以下の原則で既存構造に統合する：

「正しさ」ではなく 文脈・制約・ズレを提示対象とする

論文と同一の「3行構成フォーマット」に正規化

要約ではなく テーマとの関係性を起点に記述

検索・分類ロジックはソース別に分離（混線させない）

4.x.4 MVPとの関係

本拡張は MVPスコープ外

初期は OpenAlex 単一ソースに集中し、

構造

出力品質

ユーザー体験
を確定させる

拡張は Phase 3 以降の発展機能として検討

4.x.5 この拡張がもたらす将来的価値

論文 × 実装 × 現場知の横断ブレインストーミング

「研究として正しい」ものと
「現実で成立する」もののズレの可視化

研究・企画・プロダクト設計を貫く共通思考基盤への進化

（補足）企画全体への影響まとめ

思想：一貫（疑う・比べる・眺める）

MVP難易度：増えない

将来拡張性：明確に上がる

研究以外への横展開：現実味が増す
