# Gemini 出力ガイド（出力3行の各行ルール）

> `Gemini.md`（思考素材ジェネレーター）が出力する各行の書き方ガイド。
> 旧 `gemini_relation.md` / `gemini_summary.md` / `gemini_caution.md` を1本に統合（2026-06-23）。

## 1行目: 関係性

目的: ユーザーのテーマ/仮説と論文の接点を「観点・変数・条件」で定義する。

- 1文で完結させる。
- 「キーワード一致」や「含まれているため」は禁止。
- 観点や条件を明示し、テーマにどう接続するかを示す。

例: 〇〇という手法が、本テーマの「施設間差」という変数をどう制御しうるかという観点で関連する。

## 2行目: 要約

目的: 論文の核心をユーザー文脈に合わせて言い換える。

- 1文で完結させる。
- 原文の抜粋やコピペは禁止。必ず言い換える。
- 可能なら「対象/課題」「方法」「結果/含意」の要素を含める。

例: 単一ドメインで学習したモデルの汎化性低下を検証し、性能劣化の主要因を分析する研究である。

## 3行目: 注意点/転用/問題提起

目的: ユーザーの不安点や仮説を攻撃/拡張し、思考を揺さぶる。

- 1文で完結させる。
- 「〜の可能性がある」は避け、具体的に言い切る。
- category に応じて役割を変える（反証/地雷/転用/制約真逆）。
- cited_by_count や venue 等のメタ情報を「重み」として扱う。

例: 施設単位で分割しない評価は装置差の影響を過小評価するため、結論は実運用では崩れる。
